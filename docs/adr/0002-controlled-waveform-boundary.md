# Prove the waveform API before extracting the crate

The waveform boundary is a controlled GPUI visualization: callers own precomputed full-duration peaks, duration, position, and playback; the visualization owns pixels, hit-testing, hover presentation, focus, keyboard handling, and seek intent. We will prove this API as a private module inside `punks-app` before creating a production crate. Repeated independent GPUI waveform implementations justify a narrow future public-library exception, but not a speculative workspace crate; extraction happens only after the Punks-facing code becomes a thin adapter. The initial boundary is single-lane, uses named `Peak`/`WaveformData` values, speaks `Duration` rather than bucket indices, and excludes decoding, DSP, cache formats, windowed peaks, multichannel modes, regions, zoom, plugins, and hover callbacks.

Malformed peaks are rejected at `WaveformData` construction; empty peaks and zero duration are valid inert states. A non-inert waveform is exposed as one horizontal accessible slider whose keyboard and accessibility actions share the same clamped seek reducer. Hover time is formatted locally, and styling uses explicit GPUI-native values rather than a theme or renderer abstraction.

The element remains element-like rather than becoming a persistent playback entity. Stable caller-provided identity enables GPUI element state to cache normalized min/max envelopes by immutable peak allocation identity and integer drawable-column count. Position, duration, hover, focus, and presentation-only style changes do not invalidate that aggregation; data identity or drawable-column changes do. This keeps steady-state playback repaint work bounded by visible width without moving a rendering cache into the caller.

The private extraction has pure tests for validation, full-source mapping, clamping, keyboard/accessibility reducers, formatting, aggregation, and cache reuse, plus GPUI tests for click/focus, keyboard dispatch, hover's visual-only behavior, and inert states. GPUI's headless test context does not expose an active AccessKit tree, so role/value inspection remains a manual assistive-technology check rather than an invented test hook.
